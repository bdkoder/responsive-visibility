# How to Use Responsive Visibility

## YouTube Title

Responsive Visibility for Gutenberg Blocks | Hide or Show Blocks by Device, Breakpoints & Conditions

## YouTube Description

Learn how to use Responsive Visibility for Gutenberg blocks to hide or show content by device, custom breakpoints, and server-side conditions.

Responsive Visibility adds block visibility controls to every Gutenberg block, so you can hide a block on mobile, tablet, desktop, widescreen, or any custom breakpoint you create. It also includes Visibility Conditions for login status, user role, specific user, specific post/page, post type, page type, and shortcode.

This tutorial shows how to control block visibility inside the WordPress block editor without custom CSS or code. It is perfect for responsive layouts, member-only content, conditional blocks, and cleaner pages on smaller screens.

Use Responsive Visibility when you need:
- block visibility for mobile, tablet, desktop, and custom breakpoints
- conditional blocks based on login status or user role
- server-side visibility conditions for specific users or pages
- a simple Gutenberg workflow for hiding or showing blocks

Plugin page: https://wordpress.org/plugins/responsive-visibility/

Keywords: block visibility, conditional blocks, Gutenberg, responsive, visibility, custom breakpoints, visibility conditions, responsive Gutenberg blocks

## Voice Script

In this video, I’ll show you how to use Responsive Visibility.

First, make sure the plugin is installed and activated on your website.

Here, we have two sample sections with dummy content. Let’s use them to test the plugin step by step.

The idea is simple. You can decide which blocks should show on which devices, and you can also add server-side conditions for more control.
You do everything inside the block editor, right where the block already exists.

Select the image, then open the **Responsive Visibility** panel.
Turn on **Hide on Desktop** and **Hide on Widescreen**.

Now check the front end.
The image is hidden on those screen sizes, exactly as expected.

Turn on **Hide on Mobile** and **Hide on Tablet** too.
Now the image is hidden on mobile and tablet as well.

This is helpful when one block works well on desktop, but feels too large or too crowded on smaller screens.
Instead of removing the block completely, you can hide it only where it does not fit.

You can also customize the breakpoints to fit your layout.
If you remove **Widescreen**, you will see the change right away.
Add it back, and the rule returns.

That gives you more control than fixed mobile, tablet, and desktop settings.
If your design needs a different screen width, you can adjust it to match your site.

Let’s try one more example with the pricing blocks.
Hide the Single Pricing card on tablet.
Do the same for Family Pricing and Hope.

Now the layout feels cleaner on that screen size.
This is a simple way to keep important content readable without forcing every block to behave the same way on every device.

Now let’s look at **Visibility Conditions**.
Open the panel and set the **Login Status** condition to **Logged in**.

That means the block will show only for logged-in users.
Since we are already logged in, it appears here.
If you open the page while logged out, it stays hidden.

So this is not just a visual hide.
The content is controlled by a real condition, which makes it useful for member-only content, private notices, or content that should only appear for certain visitors.

You can also use **User Role**.
For example, show content only for **Administrator**.
If we test with a subscriber account, the block stays hidden.
Change the role to **Subscriber**, and it appears again.

That is useful when different people on the site need to see different content.
Administrators can see one thing, subscribers can see another, and guests can see something else.

You can even target one specific user.
Use the user ID in the condition.
If the ID does not match, the block stays hidden.
If it matches, the block shows for that user.

That is helpful when you want to show something to one exact account, like a team member, a client, or a special user profile.

So with Responsive Visibility, you can control blocks by screen size and by user conditions, all inside Gutenberg.

That means less custom CSS, less guesswork, and less manual work later.
You can keep the page simple for visitors and keep the editing process simple for yourself.

That’s it. Thanks for watching.
