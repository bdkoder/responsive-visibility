URL Query Param Visibility

This guide explains the URL Query Param condition inside Visibility Conditions. Use it when a block should appear only if the current URL includes a specific query string value. It is a server-side rule, so the block is removed before the page is sent to the visitor.

This feature is useful for campaign links, preview links, QA checks, and targeted landing pages. If you send people to a URL such as ?preview or ?utm_source=google, you can show or hide a block only for that request. That makes the content more controlled without needing custom code or extra plugins.

When to use it

  • Show a block only on a campaign landing page.
  • Show a block only when a preview or test link is used.
  • Show a block only for a specific traffic source such as Google or Yahoo.
  • Show a block only for one promotion code or offer URL.
  • Hide internal notes unless the URL contains a special param.

Supported syntax

The condition field accepts three common patterns. Use a plain key when you only want to check whether the parameter exists. Use key=value when you want an exact value. Use key IN [a, b] when you want multiple allowed values. The rule is still one condition, so the existing All / Any selector continues to handle how multiple rules are combined.

  • preview means the URL must contain ?preview.
  • utm_source=google means the value must be exactly google.
  • utm_source IN [google, yahoo] means either source is allowed.
  • campaign IN [summer, fall] means either campaign value is allowed.

Examples

  • Show a block only when ?preview is present.
  • Show a promo only for ?utm_source=google.
  • Show a banner for ?utm_source IN [google, yahoo].
  • Show a seasonal section for ?campaign IN [summer, fall].

How it behaves

The rule checks the current request on the server. If the query parameter is missing, the condition returns false. If the parameter is present but the value does not match, the condition also returns false. That means the block stays hidden until the exact rule is satisfied.

Because this is a Visibility Condition, it works together with the rest of the condition system. You can combine it with login status, user role, post type, page type, or a specific post/page. You can also choose whether all rules must match or any one rule is enough.

Best practices

  • Use the shortest rule that solves the problem.
  • Prefer clear campaign names and readable values.
  • Test the final URL in a front-end browser, not only in the editor.
  • Use the rule for targeted visibility, not for hiding important content without reason.
